## 일 A: 회독 레슨 (덱의 쪽 범위 하나)
- 규칙: `work\_rules\회독레슨_작성규칙.md` + 시공은 `work\interior-construction\rules\작업지시_회독레슨.md` (자료 표의 2, 3강 파일 대신 위의 새 덱 자료를 쓴다), 근현대는 과목정보.md 5절.
- 출력: `work\<과목>\lesson\<덱>_<시작3자리>-<끝3자리>.json` 과 생성 스크립트 `lesson\build_<덱>_<시작>-<끝>.py`. 기존 같은 과목 레슨 파일과 똑같은 형식 (3회독, prof 장면 금지, look 은 pass2 에만 쪽마다 1개, 근현대는 exam 장면 금지).
  근현대는 공용 도구 `lesson\build_msd_common.py` 를 기존 build 스크립트처럼 쓴다.
- 범위의 **모든 쪽**을 만든다. 범위의 PNG 를 전부 본다. look 박스 좌표는 PNG 를 보고 잡는다.
- 검사: `python tools\checkers\lesson_check.py work\<과목>\lesson\<파일>.json <시작> <끝>` 이 통과해야 한다. 시공은 추가로 `python work\interior-construction\lesson\IC_rules_check.py`.

## 일 B: 정리 슬라이드 + 문제은행 (덱 하나)
- 정리 슬라이드: `work\<과목>\notes\build_slides_w<주차>.py` -> `notes\slides_w<주차>.json`. 같은 과목의 `build_slides_w3.py` (시공) 또는 `build_slides_w6.py` (근현대) 를 본떠 공용 라이브러리 (`icslide_lib.py` / `msdslide_lib.py`) 를 쓴다.
  단원 = units_<덱>.json 의 단원 (id, 이름 그대로). 규칙 `work\_rules\정리슬라이드_작성규칙.md`.
  검사: `python tools\checkers\slide_check.py work\<과목>\notes\slides_w<주차>.json`.
- 문제은행: `work\<과목>\bank\build_<파일>.py` -> `bank\<파일>.json`. 파일 이름: 시공 L4 `l4`, L5 `l5`, 근현대 U7 `u7`, U8 `u8`, U9 `u9`.
  id 접두어도 같게 (`l4-mcq-001`, `u7-ox-003` 등). 기존 `build_l23.py` (시공) / `build_u456.py` (근현대) 패턴 그대로 (optshuffle 로 보기 섞기, check_ids).
  `part` = 주차 id, `unit` = units 의 단원 이름. 유형 비율은 기존 은행과 비슷하게 (시공: 객관식 약 50%, O/X 약 25%, 단답 약 18%, 서술 약 6%. 근현대: 기존 u456 비율). 덱 쪽수에 맞춰 시공 L4 약 70, L5 약 40, 근현대 U7 약 55, U8 약 30, U9 약 35 문항.
  규칙 `work\_rules\문제은행_작성규칙.md`. 기존 은행 파일의 id 는 절대 건드리지 않는다.
  검사: `python tools\checkers\bank_check.py work\<과목>\bank\<파일>.json`.
